# You Are the Loading Bar

A short (10–15 minute) cute 2D browser game, desktop only, in the spirit of old Friv games. A cartoon character's download is stuck; the camera dives into the computer, where the player (as the mouse cursor, the workers' boss) helps a chaotic crew of little workers (the computer's threads, on a motherboard) fix problems through quick minigames until the loading bar completes. It is a portfolio piece for freelance interactive work, so code clarity and a small, fast build matter.

## Stack

Phaser 4 + TypeScript + Vite. Art is AI-generated by the user, then cut and packed by a script here.

## Commands

- `npm run dev` — dev server at http://localhost:5273 (5173 is used by another project on this machine)
- `npm run build` — typecheck, then production build into `dist/`
- `npm run typecheck` — TypeScript only
- `npm run assets` — rebuild atlases from `art-source/` (or `node tools/build-atlas.mjs worker` for one sheet)

## Hosting

The code is on GitHub and the game is served by GitHub Pages. `.github/workflows/deploy.yml` builds and publishes on every push to `main`, so pushing is deploying. Live at https://aayushgarg293.github.io/you-are-the-loading-bar/. Link previews come from the Open Graph tags in `index.html` and `public/og-image.jpg` (a 1200×630 capture of the title screen); both hold the full live address, so update them if the address changes.

## Layout

- `art-source/` — raw AI images, kept in the repo but never shipped (`worker/`, `hamster/`, `factory/`, `ui/`, `computer/`, `minigames/`, `reference/`)
- `tools/build-atlas.mjs` — cuts named parts out of a sheet and packs an atlas; also resizes plain images
- `tools/sheets/<name>.json` — per-sheet config: source image, scale, and a pixel region for each named part (`"type": "image"` for plain pictures; per-part options `linesOnly`, `dropBackground` to lift an emblem off a flat surface, `circle` for things that spin)
- `tools/probe-sheet.mjs` — prints the bounding box of each part on a sheet, to write those regions
- `public/assets/` — generated atlases (`<name>.webp` + `<name>.json`); do not edit by hand
- `src/config.ts` — game size (1280×720), palette, pixel font
- `src/data/problems.ts` — the ordered list of breakdowns: stall percentage, which minigame scene fixes it, and the error dialog text
- `src/devMenu.ts` — dev-only HTML menu (DEV tab bottom-right, or the ` key) with a link to play each minigame directly or from just before its stall; built from `PROBLEMS`, not included in the production build
- `src/audio/sound.ts` — all sound, generated in code with the Web Audio API (no audio files): `sfx.<name>()` effects built from a `tone()` and a `noise()` primitive, and `music.play('work' | 'hurry' | 'dance')` step-sequencer loops. It borrows Phaser's audio context (`setAudioContext` in `PreloadScene`), stays silent until the context is running, and M toggles mute (remembered in localStorage)
- `src/scenes/TitleScene.ts` — title screen with the START button, whose click unlocks audio (`unlockAudio()`)
- `src/debug.ts` — URL test switches: `?scene=workshop` (with `&mood=asleep`, `&look=glasses,moustache,toolBelt,longHair`, `&carry=1`), `?scene=hamster`, `?scene=wake`, `?scene=circuit`, `?scene=blocks`, `?scene=packets`, `?scene=cpu`, `?scene=zip`, `?scene=crash`, `?scene=title`, `?scene=intro`, `?scene=ending` (add `&novideo=1` to skip the video clip), `?scene=end`, `?scene=room` (with `&mood=bored|annoyed|furious|overjoyed|stunned`), `?energy=70`, `?progress=N` (starts at N% with earlier problems solved; e.g. `?progress=23` reaches the 25% stall in a second or two). In dev the game is on `window.game`
- `src/objects/` — reusable puppets and widgets: `Worker` (moods, walking, carrying, looking, accessories, helmet status light), `SideWorker` (the same worker seen from the side: run cycle, carrying, three moods), `Hamster`, `HamsterWheel`, `LoadingBar`, `ErrorDialog` (the pop-up the scheduler holds up), `NetworkStatus` (Wi-Fi bars and speed readout), `CpuChip` (processor with temperature gauge, shared by cpu.exe and the finale)
- `src/factory/crew.ts` — the jobs factory workers do (station, sleeper, wanderer, carrier); each job reacts to running/stuck in its own way
- `src/scenes/FactoryScene.ts` — the main screen; owns the loading bar and the running/stalled state
- `src/scenes/MinigameScene.ts` — base class every minigame extends (`openWindow()` program-window frame, frustration meter, glitches as patience runs out, `addFrustration(fraction, bounce)`, `setInstruction()`, `patienceLost`, `win()`, and `outOfPatience()` which stamps REFRESH and restarts unless a minigame overrides it)
- `src/scenes/FeedHamsterScene.ts` (power.exe), `WakeWorkersScene.ts` (threads.exe), `CircuitScene.ts` (network.exe), `CorruptedBlocksScene.ts` (antivirus.exe), `PacketDeliveryScene.ts` (packets.exe), `CpuCoolingScene.ts` (cpu.exe), `ZipFileScene.ts` (zip.exe), `CrashScene.ts` (system.exe, the finale) — the eight minigames; file names predate the computer theme
- `src/scenes/WorkshopScene.ts` — rig test bench, not part of the final game
- The real world outside the computer is drawn entirely in code, in the style of classic Flash stick-figure animations (user's references are in `art-source/reference/stick-style/`, which is git-ignored because they are screenshots of another game and of the user's desktop; take the style, not the character): thin black lines, big white head with two wisps of hair, curved limbs, white hands, brown shoes, flat grey rooms with a few colour accents. The user wants a 3D feel, achieved with perspective-drawn sets, different camera angles per shot, depth scaling and camera moves (not real 3D).
  - `src/objects/StickFigure.ts` — side view; posed by a handful of numbers with two-bone arm reach; ready-made moods plus `poseTo()`, `setFace()`, `setHoldingMug()` for cutscenes
  - `src/objects/StickFigureFront.ts` — front view, slumped walk towards the camera, yawn
  - `src/cutscene/sets.ts` — the rooms: `drawWideRoom` (one-point perspective) and `drawDeskSet` (side view at the desk); each returns the pieces a cutscene animates
  - `src/cutscene/closeups.ts` — close-up drawings: `BigFace` (expressions, eyebrow twitch), mug in hand, tower power button, over-the-shoulder monitor, and the screen-filling download window
  - `src/scenes/IntroScene.ts` — the opening cutscene (about 35 s, 11 shots, skippable) as a Phaser timeline. Each shot method returns its moments and its length, each shot is a Container, `cutTo()` switches shots and resets the camera, and a second fixed camera films the SKIP button (anything added to a shot later must be `fixedCamera.ignore`d). It ends by zooming into the monitor and starting `Factory`. The game now opens with it; `?progress=N` skips it
  - `src/scenes/EndingScene.ts` — the ending: pull out of the monitor at 100%, joy, then the player clicks OPEN on the file (the click is what lets the browser play sound). The wrong file is a rickroll: the first five seconds of the real video (`public/assets/video/rickroll.mp4`, 600×400 to fit the drawn monitor, cut with ffmpeg from the user's local copy, about 360 KB), played as a Phaser `Video` inside the shot. The user chose this over the earlier YouTube embed (2026-10-27) because friends testing it saw adverts. The reaction (face, shout, cut to black at 5 s) fits inside the clip. If the clip has not shown a frame within 3 s, or errors, it falls back to our own version, three workers dancing under "NEVER GONNA LOAD YOU UP". Then `EndScreen`. Keep the clip this short; don't add more of the song or footage
  - `src/scenes/EndScreenScene.ts` — star rating (saved in localStorage only), PLAY AGAIN, SHARE (copies the address), THE REAL SONG (opens YouTube), and the user's Buy Me a Coffee button (an HTML link placed with Phaser's `this.add.dom`, which needs `dom: { createContainer: true }` in the game config)
  - `src/scenes/RoomScene.ts` — test bench for the side-view figure's moods

## Conventions

- Characters are cutout puppets: parts in a `Container`, animated with tweens, no frame-by-frame sheets.
- A character's container origin is the ground between its feet.
- New art: add the raw image to `art-source/`, add a `tools/sheets/<name>.json`, run `npm run assets`, load it in `PreloadScene`.
- The worker atlas holds the body (from `worker/thread-parts.png`); eyes and mouths are a separate `faces` atlas cut from the old `worker/parts.png`.
- In both worker puppets the forearm is drawn over the upper arm, so the glove end hides the elbow joint.
- The helmet art is white so `hatTint` becomes its colour.
- Import Phaser as `import * as Phaser from 'phaser'`.
- Don't name a class field `body` on a Phaser game object; it clashes with the built-in physics body.
- When a mood or animation starts from a pose, set that pose explicitly before adding the tween, or the first frame shows the old pose.
- Anything a job schedules for later must go through its shift guard (`makeShift` in `crew.ts`) so it is ignored if the factory state has flipped since.

## Working with the user

- After building anything, explain what was built and walk through the key code with both an analogy and the technical meaning. The user is learning Phaser from this project.
- "Discussion mode" means talk only; build nothing until told to.
- Check visual work in a real browser before reporting it done (headless Chrome with `--enable-unsafe-swiftshader` renders the game).

## Plan

The whole middle of the game is playable: the motherboard screen stalls at 1%, 12%, 25%, 40%, 55%, 70%, 85% and 99%; each stall opens its minigame; after the eighth the bar reaches 100% and the crew cheers under a "DOWNLOAD COMPLETE!" banner (`FactoryScene.downloadComplete`, where the ending cutscene will hook in).

Everything is themed as computer puns (agreed 2026-10-09, built for the factory screen and minigames 1–4 on 2026-10-11). Text labels and error messages are allowed. The eight minigames, in `src/data/problems.ts`:

1. 1% low power — drag seeds to the hamster to charge a battery meter (built)
2. 12% sleep mode — threads freeze as "Not Responding"; wiggle the mouse over them to wake them before the data bus backs up (built)
3. 25% no connection — rotate circuit tiles so gold traces join the router to the download port; traces drawn in code, puzzle generated from a random route so it is always solvable (built)
4. 40% antivirus — click viruses into the Recycle Bin, let clean blocks pass; Trojans look like a clean block with a horse emblem until near the end of the belt (built)
5. 55% packet delivery — an endless-runner: Up/Down (or W/S) switch between three ribbon cables to dodge pop-ups, spam, cookies, 404 signs and snails; spawning always leaves one cable clear (built)
6. 70% CPU overheating — hold the mouse button (or Space) to crank the fan, release to rest; keep the gauge needle in the green for 14 seconds in total while the workload (heat) keeps changing; too cold counts as "frozen" (built)
7. 85% file too large — tap Left/Right (or A/D) in turn so two workers jump on a bulging folder; it springs back, so keep the rhythm until it is zipped (built)
8. 99% prevent the crash — seven six-second micro versions of minigames 1–7 in order; a blue screen rises with the patience meter (slow drain plus 0.2 per failed round); if it fills, a full blue screen of death plays and the finale restarts. Each round registers its props and listeners with `keep()`/`listen()` so `clearRound()` can wipe them (built)

World: hamster wheel = power supply, conveyor = data bus, block pile = cache, wall fan = CPU fan (a spinning copy of the painted blades sits on top), router on the right wall. Crew roles by name tag: `thread_NN`, `daemon` (sleeper), `zombie` and `idle.exe` (wanderers), `scheduler` (reporter).

The download is called `taylor_drift_new_single.mp3` (`DOWNLOAD_FILE` in `src/config.ts`; a parody name on purpose). The whole game now runs start to finish: intro → main screen and eight minigames → ending → end screen.

Flow: title → intro → main screen and eight minigames → ending → end screen → title. Music follows the state: `work` while the line runs, silence when it stalls, `hurry` inside a minigame. Sound hooks sit next to the action they belong to; cutscenes use `cue(at, sfx.name)` moments. Nobody has listened to the sound yet (it was only checked for errors and that sounds are scheduled), so volumes and tunes need the user's ears.

Still to do: sound tuning by ear, difficulty tuning by a human player, a garbage-collector worker, jobs that need the side view, a larger crew. Art in `art-source/` not yet used: the heat sink in `computer/cpu.png`, the spinner, clipboard and signboard in `computer/zip.png`. The old factory art (`factory/background.png`, `worker/parts.png` body parts, `minigames/*.png` other than `props.png`) is superseded.

## Adding a minigame

1. Create `src/scenes/<Name>Scene.ts` extending `MinigameScene`; build the screen in `create()`, call `this.openWindow(title, instruction)` and `this.startFrustration(seconds)` and `this.win()` when solved; call `super.update()` if overriding `update`.
2. Register the scene in `src/main.ts`.
3. Add a line to `PROBLEMS` in `src/data/problems.ts`.
4. In that `PROBLEMS` line set `error` (dialog title, message and icon), `powerOut` (does the hamster stop?) and `crewMood` (force the whole crew into one mood) to give the factory its broken-state look; anything more specific goes in `FactoryScene.setRunning`.
5. Add a `?scene=` shortcut in `PreloadScene` for testing.
